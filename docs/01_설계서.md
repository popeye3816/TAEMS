# 기술지원 통합관리 시스템 — 설계서 v0.1

작성일 2026-10-15 · 상태: 초안(검토 중)

## 1. 목적

고객사별 점검기록·이슈·담당자·버전 정보를 한곳에 모으고, 엔지니어 배정과 월별 기술지원 일정을 관리하며, 처리 경험을 지식으로 축적한다.

| 기존 문제 | 해결 방법 |
|---|---|
| 정보 분산 (엑셀·폴더·개인 메모) | 고객사 상세 한 화면에 시스템/버전, 담당자, 계약, 점검이력, 이슈, 문서, 접속정보 통합 |
| 담당자 의존 (인수인계 문서 수작업) | 고객사별 정·부 담당 엔지니어, 배정 이력 보존, 인수인계 항목을 고객사 필드로 상시 관리 |
| 답변 지연 | 이슈 경과시간 표시, 미배정·장기 미처리 알림 |
| 업무량 불균형 | 엔지니어별 담당 고객사·월 점검 건수·진행 이슈 현황판, 피크월(3·6·9·12월) 사전 경고 |
| 같은 문제 반복 | 이슈 완료 시 원인/조치 필수 입력 → KB 등록, 이슈 등록 시 유사 KB 추천 |

## 2. 기술 스택 · 운영

- **Frontend/Backend**: Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui
- **DB/Auth/Storage**: Supabase (Postgres, Auth, Storage, RLS)
- **배포**: Vercel (Cron으로 일일 알림 배치)
- **메일**: Resend (또는 회사 SMTP)
- **메신저**: 카카오워크 Bot API + Slack Incoming Webhook **둘 다** 사용 (`Notifier` 인터페이스로 채널 추상화)
- **허용 도메인**: `@unipoint.co.kr`, 최초 관리자 `chlee@unipoint.co.kr`
- **민감정보 암호화**: AES-256-GCM 애플리케이션 레벨 암호화, 키는 Vercel 환경변수에만 보관
- 규모: 엔지니어 10~30명, 고객사 50~200곳 → Supabase Pro 1개 프로젝트로 충분

## 3. 사용자 · 권한

| 역할 | 할 수 있는 일 |
|---|---|
| **관리자** | 전체 CRUD, 사용자 계정 생성, 엔지니어 배정, 월 일정 확정, 통계, 양식 관리, 엑셀 가져오기 |
| **엔지니어** | 전체 고객사·이슈·KB 조회, 본인 점검/이슈 처리, 결과서 업로드, KB 작성. 접속계정 열람은 **담당 고객사만** |
| **영업** | 담당 고객사의 **점검 완료 내역과 결과서 다운로드만** 가능. 결과서 업로드 시 알림 수신 |

- 로그인: 회사 이메일 + 비밀번호(Supabase Auth). 회원가입 비활성화, 관리자가 초대.
- 권한은 DB의 RLS(Row Level Security)로 강제한다. 화면에서만 숨기지 않는다.

### 4.1 고객사

**customers** — 유지보수 사이트 1건 = 1행 (예: 씨티은행 인천 / 씨티은행 문래동은 별도 행, `group_name`으로 묶음)

| 컬럼 | 설명 | 엑셀 출처 |
|---|---|---|
| name, group_name | 사이트명, 고객 그룹 | MA.고객 |
| business_unit | 영업팀 | MA.영업팀 |
| sales_rep_id → profiles | 영업대표 | MA.영업대표(**2번째 열만**, 16번째 열 무시) / 계약.Sales Rep |
| importance | 상/중/하 | MA.중요도 |
| service_difficulty | 상/중/하 | MA.Service 난이도 |
| support_level | 1차(누구나) / 2차(고급 엔지니어 필요) | MA.1차/2차 |
| remote_access | 가능/부분/불가 | MA.원격 가능 |
| business_scope | 업무 범위 | MA.업무 |
| address, visit_procedure | 위치, 출입 절차 | 인수인계서 |
| support_method | 지원 방법(일정 조율 방식 등) | 인수인계서 |
| incident_procedure | 장애 시 조치 절차 | 인수인계서 |
| site_notes, contact_temperament | 특이사항, 담당자 성향 | 인수인계서 / MA.이슈 |
| status | 진행 / 계약종료 | |

**customer_systems** — 서버(호스트) 단위. 결과서의 “점검 대상” 표와 같은 구조
- business_name(업무명), group_label(결과서 페이지 단위 묶음, 예: “전자도서관”), environment(운영/개발)
- hostname, `ip_enc`(IP:Port, 암호화), os, cpu, memory
- product(WAS/IHS/Jennifer/Liberty/기타), version(Fix Level 포함), edition(ND/BASE), license_count
- java_version, install_path, log_path, dump_path

**customer_licenses** (뷰) — 고객사·제품·에디션별 라이선스 합계

**customer_contacts** — 이름, 직급, 소속(중간업체 포함), 전화, 이메일, 주담당 여부, 변경 이력 메모

**customer_credentials** — 시스템별 계정, `username_enc`, `password_enc`, 메모. 열람 시 `credential_access_logs`에 누가·언제 기록.

### 4.2 계약

**contracts** — contract_no(PJT…), contractor(계약처/중간업체), end_user, 계약기간(시작·종료), 금액, 유형(MA/WA/PS/퍼콜), 제품, 자동연장 여부, 대가 청구 방식 메모(“매월 점검 검수요청”, “분기 발행” 등)

### 4.3 배정 · 점검

**engineer_assignments** — customer, engineer, role(정/부), 시작일, 종료일. 종료일을 채워 이력을 남김(인수인계 기록 대체).

**inspection_plans** — 고객사별 점검 주기
- cycle: 매월 / 격월 / 분기 / 반기 / 연 / 퍼콜
- months: 점검 월 배열 (예 `{3,6,9,12}`, `{1,4,7,10}`, `{2,5,11}`)
- preferred_timing: “월 하순”, “20일 전” 등 자유 입력
- method: 방문 / 원격 / 혼합(예: 매월 원격 + 분기 방문)

**inspections** — 월별 점검 1건
- 상태: `예정 → 일정확정 → 점검완료 → 결과서제출` (+ `취소`)
- 연월, 예정일, 확정일, 담당 엔지니어, 방식, 점검 요약, 발견사항
- 관리자가 “다음 달 일정 생성”을 누르면 plans 기준으로 자동 생성

점검 항목별 결과 입력(checklist_*, inspection_results)은 하지 않기로 했다(2026-10-15). 결과서·사진 파일만 올려 공유한다.

**inspection_reports** — Supabase Storage 파일 경로, 버전, 업로드자, 업로드 시각, `customer_signed`(고객 서명본 여부). 업로드되면 해당 고객사 영업에게 알림.

**report_templates** — 회사 표준 양식(customer_id 없음) + 고객사 전용 양식, 제품별, 버전 관리

### 4.4 이슈

**issues**
- 고객사, 관련 시스템, 제목, 내용, 심각도(긴급/높음/보통/낮음), 접수 경로(전화/메일/메신저/점검 중 발견), 고객 측 요청자
- 상태: `접수 → 배정 → 처리중 → 완료`
- 시각 기록: received_at, assigned_at, started_at, resolved_at (처리시간 통계용)
- 완료 시 **원인(cause)·조치(action) 필수**, “KB로 등록” 체크
- 첨부: 로그, 스크린샷

**issue_activities** — 댓글, 상태 변경, 담당자 변경 이력

### 4.5 지식베이스

**kb_articles** — 제목, 분류(WAS/APM/OS/DB/네트워크), 제품, 버전, 증상, 원인, 해결방법, 환경정보, 태그, 원본 이슈, 고객사(선택), 작성자, 상태(초안/게시)
- 검색: Postgres `pg_trgm` 유사도 검색 (한글 형태소 분석기가 없어서 trigram 사용)
- 이슈 등록 화면에서 제목·내용 입력 중 유사 KB 상위 5건 자동 추천
- 기존 `_공통/*.md` SOP 문서와 Trouble Shooting Cases 엑셀을 초기 KB로 가져옴

### 4.6 공통

- **attachments** — 엔티티별 파일(이슈·KB·고객사 문서)
- **notifications** — 사용자별 시스템 내 알림, 읽음 여부
- **notification_deliveries** — 채널(email/kakaowork/slack)별 발송 결과
- **audit_logs** — 주요 변경 이력

## 5. 알림 규칙

| 이벤트 | 받는 사람 | 채널 |
|---|---|---|
| 이슈 배정 | 담당 엔지니어 | 시스템 + 메일 + 메신저 |
| 긴급 이슈 접수 | 관리자 전체 | 시스템 + 메신저 |
| 이슈 미배정 4시간 / 처리중 N일 초과 | 관리자 | 시스템 + 메신저 |
| 점검 D-3 | 담당 엔지니어 | 시스템 + 메신저 |
| 월말까지 점검 미완료 | 관리자 + 담당 엔지니어 | 시스템 + 메일 |
| **결과서 업로드** | **해당 고객사 영업** | **메일(다운로드 링크) + 메신저** |
| 계약 만료 60일 전 | 영업 + 관리자 | 메일 |

정기 알림은 Vercel Cron이 매일 오전 8시(KST)에 한 번 실행한다.

## 6. 화면 구성

1. **대시보드** — 역할별
   - 관리자: 이번 달 점검 진행률, 미배정/지연 이슈, 엔지니어 업무량, 결과서 미제출
   - 엔지니어: 내 이번 주 점검, 내 이슈, 최근 KB
   - 영업: 내 고객사의 이번 달 결과서 목록(다운로드)
2. **고객사** — 목록(필터: 제품, 영업팀, 담당 엔지니어, 주기) / 상세 탭: 개요·시스템·담당자·계약·점검이력·이슈·문서·접속정보
3. **월별 일정** — 캘린더 보기 + 엔지니어별 보기, 다음 달 일정 자동 생성, 지역별 묶음 표시(여의도·인천·부산)
4. **점검 상세** — 체크리스트, 요약, 결과서 양식 다운로드·업로드
5. **이슈** — 목록 / 칸반(접수·배정·처리중·완료) / 상세
6. **지식베이스** — 검색, 상세, 작성·편집
7. **업무량** — 엔지니어 × 월 히트맵, 담당 고객사 수, 평균 처리시간
8. **관리** — 사용자·역할, 결과서 양식, 엑셀 가져오기, 알림 설정

## 8. 보안

- 모든 테이블에 RLS 적용, 역할(profiles.role)과 담당 배정 기준으로 행 접근 제어
- IP·계정·비밀번호는 서버에서만 암·복호화(키는 `ENCRYPTION_KEY` 환경변수). 브라우저와 DB에는 암호문만 존재
- 접속정보는 “보기” 버튼을 눌러야 표시되고, 열람할 때마다 로그 기록
- Storage 버킷 비공개, 다운로드는 만료 시간이 있는 서명 URL로만 제공
- 고객 연락처 등 개인정보는 사내 사용자만 접근

## 9. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 프로젝트 셋업, 로그인, 역할, 기본 레이아웃 | 3개 역할로 로그인하고 메뉴가 다르게 보임 |
| 2 | 고객사·시스템·담당자·계약·배정 + 엑셀 가져오기 | MA·계약·인수인계 데이터가 고객사 상세에 표시 |
| 3 | 점검 주기·월별 일정·결과서 양식/업로드 | 다음 달 일정 자동 생성, 업로드 시 영업 화면에 노출 |
| 4 | 이슈 관리 | 접수→완료 흐름, 원인/조치 필수 |
| 5 | 지식베이스 + 유사 추천 | 이슈 완료 → KB 등록, 이슈 등록 시 추천 |
| 6 | 알림(메일·메신저·Cron), 대시보드·업무량 | 결과서 업로드 시 영업에게 메일 도착 |
| 7 | Vercel·Supabase 운영 배포 | 사내 사용자 접속 |
