### B. 다른 PC

1. 저장소 받기
   ```bash
   git clone https://github.com/popeye3816/TAEMS.git
   ```
2. `npm install` (Node 24 권장, Python 3.12 + `openpyxl`은 엑셀 가져오기 때만)
3. **비밀값 파일 옮기기** (git에 없음, 메일·메신저로 보내지 말 것 — USB나 회사 비밀번호 관리 도구로):
   - `.env.local` → 새 PC의 프로젝트 폴더에 그대로
   - 특히 `ENCRYPTION_KEY`가 없으면 고객 IP·계정을 복호화할 수 없다
   - 또는 Vercel에서 받기: `npx vercel login` → `npx vercel link` → `npx vercel env pull .env.local` (단 `--sensitive`로 넣은 SUPABASE_SECRET_KEY·ENCRYPTION_KEY·CRON_SECRET은 내려받기 안 됨 → 직접 옮겨야 함)
4. 각 서비스 로그인은 **사람이 직접** 한다 (Claude는 비밀번호를 입력하지 않는다)
   ```bash
   npx supabase login
   ```
   ```bash
   npx supabase link --project-ref ohhscbjidndsslfcobsd
   ```
   ```bash
   npx vercel login
   ```
   GitHub는 첫 `git push` 때 로그인 창이 뜬다 (popeye3816 계정 또는 쓰기 권한이 있는 계정).
5. Claude Code에서 폴더를 열고 A-3과 같이 시작

## 6. 진행 중이던 작업 (2026-10-15 17시 기준, 다른 아이디로 이어서 진행)

### 6-1. 요청: 내 PC 개발환경(로컬 Supabase) → 검증 → 운영 배포 흐름 구축

사용자 요청: "개발환경으로 supabase를 내 PC에 구축하고, 내 PC에서 이상 없을 때 운영으로 배포되는 환경을 구축해 달라"

합의된 설계 (아직 구현 전):
1. **로컬 Supabase**: `npx supabase start` (Docker 필요) → `127.0.0.1:54321`. 마이그레이션은 `npx supabase db reset`으로 적용
2. **환경 분리**: `.env.development.local`(로컬 Supabase 값)을 만들면 `npm run dev`는 로컬 DB를 쓴다(Next.js에서 `.env.local`보다 우선). 운영 키는 `.env.local`에 그대로 두고 스크립트(`backup`, `import:*`)만 사용
3. **예제 데이터·테스트 계정**: 실제 고객 정보가 아닌 가짜 데이터로 시드 스크립트 작성, 관리자·엔지니어·영업 테스트 계정 생성 → 로컬에서는 Claude가 로그인 화면까지 직접 검증 가능 (localhost + 테스트 계정)
4. **GitHub Actions CI**: push·PR마다 typecheck·lint·build + 빈 Postgres에 마이그레이션 전체 적용 검사(`supabase/setup-cli`, `supabase db start`)
5. **배포**: `main`만 운영 배포(vercel.json `git.deploymentEnabled`로 다른 브랜치 배포 끄기 검토 — Preview 환경변수가 운영 DB를 가리키므로). DB 변경은 `npm run release` 같은 스크립트로 `supabase db push --dry-run` 확인 → 반영 → main push

### 6-2. 막혀 있는 것: Docker Desktop 엔진이 켜지지 않음

- 증상: Docker Desktop(4.80.0)은 실행되지만 `docker info` 응답 없음, `wsl -l -v`에서 `docker-desktop`이 Stopped
- 원인: 백엔드가 시작할 때 **오래된 유닉스 소켓 파일(2026-10-01 생성)을 지우지 못해 충돌**한다 (`%LOCALAPPDATA%\Docker\log\host\com.docker.backend.exe.log`의 "backend crashed")
  1. `%LOCALAPPDATA%\Docker\run\dockerInference` → **해결함**: `run` 폴더를 `run.old-20261015`로 이름 변경(삭제는 안 됨, 이름 변경은 됨)
  2. `%LOCALAPPDATA%\docker-secrets-engine\engine.sock` → **다음 할 일**: Docker Desktop 종료 → 이 폴더를 `docker-secrets-engine.old-20261015`로 이름 변경 → Docker Desktop 다시 실행
  3. 같은 종류의 소켓 파일이 더 나오면 같은 방법으로 처리. 계속되면 Docker Desktop 설정에서 AI 기능(`EnableDockerAI`, `%APPDATA%\Docker\settings-store.json`) 끄기, Docker Desktop 업데이트, 또는 Troubleshoot › Reset to factory defaults 검토(사용자 확인 필요)
- Docker 종료 명령(PowerShell): `Get-Process "Docker Desktop","com.docker.backend" | Stop-Process -Force; wsl --shutdown`
