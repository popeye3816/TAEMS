### 환경변수 (Vercel › Settings › Environment Variables)

| 이름 | 용도 | 비고 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | DB 연결 | 공개돼도 되는 값 |
| `SUPABASE_SECRET_KEY` | 서버 전용 관리자 키 | **유출 금지**. 유출 시 Supabase에서 키를 새로 만들고 교체 |
| `ENCRYPTION_KEY` | 고객 IP·계정 암호화 | **잃어버리면 암호화된 값 복구 불가. 바꾸면 기존 값을 못 읽음.** 회사 비밀번호 관리 도구에 별도 보관 |
| `CRON_SECRET` | 매일 아침 알림 호출 인증 | |
| `APP_URL` | 알림 속 링크 | `https://taems.vercel.app` |
| `RESEND_API_KEY`, `MAIL_FROM` / `KAKAOWORK_BOT_KEY` / `SLACK_WEBHOOK_URL` | 외부 알림 | 비어 있으면 그 채널은 건너뜀 |

로컬 개발용 값은 `.env.local`(git 제외)에 있고, 사본이 `.secrets/env-backup.txt`에 있다.

## 2. 사용자 관리

- **계정 만들기**: 사용자 관리 › "여러 명 한꺼번에 등록"에 `이름, 이메일, 역할`을 줄마다 붙여넣는다. 임시 비밀번호가 화면에 한 번만 나오므로 CSV로 저장하거나 바로 본인에게 개인 메시지로 전달한다.
- 처음 로그인하면 모든 화면 위에 "비밀번호를 바꿔 주세요" 안내가 나온다.
- **비밀번호를 잊었을 때**: 사용자 목록에서 "임시 비밀번호 재발급".
- **퇴사·휴직**: 사용자 목록에서 "활성" 체크 해제 → 로그인 차단. 직원 명단에서도 "재직" 해제. 담당 고객사는 고객사 › 담당 엔지니어 탭에서 다른 사람에게 넘긴다(이력이 남는다).
- **영업 담당자**는 계정이 없어도 직원 명단에 이메일만 넣으면 결과서 알림을 받는다.
- 회원가입은 막혀 있고, `@unipoint.co.kr`만 등록된다.

## 4. 백업

Supabase 무료 플랜은 자동 백업을 내려받을 수 없다. 매월 1회 이상 이 PC에서 실행한다.

```bash
npm run backup -- --files
```

`backups/<날짜-시각>/`에 모든 표(JSON)와 올린 파일이 저장된다. 고객 정보가 들어 있으므로 회사 보안 저장소로 옮기고 PC에서는 지운다.

## 5. 장애 대응

| 증상 | 확인할 곳 |
|---|---|
| 사이트가 안 열림 | Vercel › Deployments 최신 배포가 Ready인지. 실패면 이전 배포에서 "Promote to Production" |
| 로그인이 안 됨 | 화면의 오류 코드 확인. Supabase › Authentication › Sign In / Providers에서 **Email이 켜져 있는지** (꺼지면 전원 로그인 불가) |
| 화면에 "오류 번호"가 나옴 | Vercel › Logs에서 그 번호 검색 |
| 알림이 안 옴 | 사용자 관리 › 알림 채널의 상태와 발송 기록. 실패 사유가 기록돼 있다 |
| 아침 알림이 안 옴 | Vercel › Settings › Cron Jobs 실행 기록 |
| DB 작업 중 실수 | 가장 최근 `backups/` 폴더의 JSON으로 복구 (개발자 작업 필요) |

## 6. 개발·변경

- 코드 수정 → GitHub main에 push → Vercel이 1분 안에 자동 배포
- DB 변경은 `supabase/migrations/`에 SQL 파일을 추가하고 `npx supabase db push`
- 보안 점검: `npx supabase db advisors --linked` (2026-10-15 기준 남은 경고 2종은 의도된 것: 권한 확인 함수, 유출 비밀번호 검사는 유료 기능)
